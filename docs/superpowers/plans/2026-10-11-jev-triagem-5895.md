# Jev Triagem 5895 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Classificar uma vez as mensagens livres recebidas no 5895 com Jev e encaminhar a ação comercial correta aos workflows n8n, sem atrasar o início do funil de anúncio.

**Architecture:** O bridge mantém a detecção de anúncio e as regras exatas antes da inferência. Um módulo compartilhado faz a escolha tipada no TypeSafe, grava uma decisão idempotente e devolve uma ação fechada; os três adaptadores de entrada a consomem e reutilizam os handlers atuais que já despacham para o n8n. Timeout ou baixa confiança preservam o classificador determinístico atual.

**Tech Stack:** Deno/TypeScript, TypeSafe System One (`jev-latest`), Supabase Postgres, webhooks n8n do 5895.

**Spec:** `docs/superpowers/specs/2026-10-11-jev-triagem-5895-design.md`

## Global Constraints

- Aplicar somente ao inbox oficial 5895. Conferir o canal com `mainFunnelForChannel(channel) === RESTORED_5895_FUNNEL`.
- Iniciar a inscrição de anúncio sem aguardar Jev. Preservar primeira peça rápida e janela de entrega 06h–21h.
- Um ID de mensagem estável produz no máximo uma chamada Jev e um despacho automático. Não usar timestamp atual nem UUID aleatório como fallback de identidade.
- Botões, comandos, opt-out, fechamento, comprovante, preço, horário e deduplicação permanecem determinísticos.
- Jev só escolhe valores de um conjunto fechado; o bridge valida confiança e contrato antes de acionar n8n.
- Enviar ao TypeSafe apenas texto necessário à classificação e contexto mínimo, sem histórico inteiro, telefone ou segredo.
- Não reprocessar mensagens históricas nem ativar Jev em outros canais na publicação.
- Instrução superior desta tarefa: não adicionar nem executar testes sem pedido explícito do usuário. A lista de cenários em cada tarefa serve como contrato de revisão e futura verificação autorizada.

### Task 1: Registro idempotente e contrato de decisão

**Files:**
- Create: `supabase/migrations/20261011_jev_5895_intent_decisions.sql`

**Interfaces:**
- Produces: `JevIntentAction = "preco" | "video" | "plantio" | "nutricao" | "catalogo" | "logistica" | "duvida_tecnica" | "humano" | "nenhuma"`.
- Produces: `JevIntentInput { channelId: string; source: "chatwoot" | "uazapi" | "facebook"; providerMessageId?: string | null; sourceMessageId: string; conversationId: string | null; text: string; adOrigin: boolean }`.

- [ ] **Step 1: Criar migração.** Usar chave primária composta `(channel_id, message_key)` e campos `source`, `conversation_id`, `status` (`processing`, `succeeded`, `low_confidence`, `timeout`, `failed`, `skipped`), `action`, `confidence`, `model`, `input_tokens`, `output_tokens`, `latency_ms`, `reason_code`, `dispatch_status` (`none`, `queued`, `accepted`, `failed`), `created_at`, `finished_at`. Adicionar índice `(created_at, status)`, `CHECK` para status/ação/despacho e RLS sem policy de acesso público. Serviço usa a conexão admin existente.

```sql
create table if not exists jev_intent_decisions (
  channel_id uuid not null references channels(id),
  message_key text not null,
  source text not null check (source in ('chatwoot','uazapi','facebook')),
  conversation_id uuid references conversations(id),
  status text not null check (status in ('processing','succeeded','low_confidence','timeout','failed','skipped')),
  action text check (action in ('preco','video','plantio','nutricao','catalogo','logistica','duvida_tecnica','humano','nenhuma')),
  confidence numeric(4,3),
  model text,
  input_tokens int,
  output_tokens int,
  latency_ms int,
  reason_code text,
  dispatch_status text not null default 'none' check (dispatch_status in ('none','queued','accepted','failed')),
  created_at timestamptz not null default now(),
  finished_at timestamptz,
  primary key (channel_id, message_key)
);
create index if not exists idx_jev_intent_day_status on jev_intent_decisions(created_at, status);
alter table jev_intent_decisions enable row level security;
```
- [ ] **Step 2: Definir identidade estável.** `messageKey` usa `provider:<id>` se o ID do provedor está presente; caso contrário `source:<source>:<sourceMessageId>`. Se ambos faltarem, registrar `skipped` em log estruturado sem chamar Jev nem enviar nova ação. A chave de origem não inclui texto nem telefone.

```ts
export function jevMessageKey(input: JevIntentInput): string | null {
  if (input.providerMessageId?.trim()) return `provider:${input.providerMessageId.trim()}`;
  if (input.sourceMessageId.trim()) return `source:${input.source}:${input.sourceMessageId.trim()}`;
  return null;
}
```
- [ ] **Step 3: Reservar a decisão.** `INSERT ... ON CONFLICT DO NOTHING` antes de chamar Jev; conflito retorna o resultado existente ou `none` enquanto estiver `processing`. Se o processo morrer, não tentar automaticamente uma segunda chamada; recuperação manual exige comando explícito.
- [ ] **Step 4: Adicionar configuração.** `SOBERANO_JEV_INTENT_ENABLED=false` por padrão, `SOBERANO_JEV_INTENT_TIMEOUT_MS=2000`, `SOBERANO_JEV_INTENT_MODEL=jev-latest`. A chave TypeSafe vem da variável existente `TYPESAFE_API_KEY` e nunca aparece em logs.
- [ ] **Step 5: Revisar os cenários** de duplicação de webhook, IDs diferentes por origem, ausência de ID, canal fora do 5895 e desligamento da flag. Não criar nem rodar testes sem novo pedido.
- [ ] **Step 6: Commit** apenas dos arquivos desta tarefa, após revisão do diff.

  .replace(/[\w.+-]+@[\w.-]+\.[a-z]{2,}/gi, "[email]")

const body = {

### Task 4: Contagem operacional e publicação controlada

**Files:**

**Interfaces:**
- Consumes: `jev_intent_decisions` da Task 1.
- Produces: consultas diárias de elegíveis, tentativas, sucesso, baixa confiança, falha, tokens, duração e despacho.

- [ ] **Step 1: Escrever consultas de uso.** Agrupar por dia em `America/Fortaleza`, `status` e `action`; somar tokens disponíveis, contar `accepted`/`failed`, calcular percentis de `latency_ms` somente para chamadas efetuadas. Não calcular custo sem tarifa confirmada.

```sql
select (created_at at time zone 'America/Fortaleza')::date as dia,
       status, coalesce(action, 'sem_acao') as acao,
       count(*) as mensagens,
       sum(coalesce(input_tokens, 0) + coalesce(output_tokens, 0)) as tokens,
       count(*) filter (where dispatch_status = 'accepted') as acoes_aceitas,
       percentile_cont(0.95) within group (order by latency_ms)
         filter (where latency_ms is not null) as latencia_p95_ms
from jev_intent_decisions
group by 1, 2, 3
order by dia desc, status, acao;
```
